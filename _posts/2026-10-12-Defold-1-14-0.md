**Defold 1.14.0 is now available!** Released today, October 12, this version brings new tools for custom rendering and several improvements to everyday work in the editor. Cubemap render targets open up new possibilities for reflections and environment capture, the Material Editor gets a clearer layout, and macOS games now use Metal by default.

This release also prepares Defold for **iPhone Duo** and adds **Microsoft Xbox support** expanding the platforms you can reach with your games. We will cover Xbox support in a separate announcement.

## Highlights in Defold 1.14.0

* **Microsoft Xbox support**
* **Ready for iPhone Duo**, with improvements to iOS lifecycle handling and mobile GUI layouts
* **Cubemap render targets** - handy for custom reflections and other rendering effects
* **A redesigned Material Editor** with clearer sections and focused editing forms
* **Generational game object handles** and support for up to 1,048,576 game objects per collection
* **Reduced editor CPU usage** when working with multiple tabs, resizing, and editing properties
* **Better editor text shaping** for complex scripts, emojis, and bidirectional text
* **Metal by default on macOS**
* **Shader storage buffers in dmSDK** for native graphics and compute extensions
* **Configurable tab navigation and reordering shortcuts**, plus wildcard patterns in `.defignore` and `.defunload`

## Xbox support

Since Defold 1.14.0 you can build your games for  **Microsoft Xbox console**. This is another step in making Defold available across desktop, mobile, web, and console platforms, giving developers more opportunities to bring their games to players.

We will share the details of Xbox support and how to get started in a dedicated blog post.

## Ready for iPhone Duo

Preparing Defold for **iPhone Duo** has been an important part of this release. Defold 1.14.0 brings improvements to iOS app lifecycle handling, links, and GUI safe-area and rotation updates.

For developers bringing their games to iPhone Duo, this release should be the starting point for building and testing their projects on the new device.

## Cubemap render targets

Defold can now render directly into a cubemap. You can create a cubemap render target in a render script or configure it as a `.render_target` resource in the editor, then select which of its six faces to draw into.

This gives custom render pipelines a way to capture a scene in every direction from a chosen point. You can use those views to build real-time reflections, environment capture, point-light shadows, and other effects that need more than a single camera view. These effects are implemented in your rendering pipeline using the new targets.

The color attachment can be sampled in a shader with `samplerCube`. Cubemap attachments must be square and equally sized, and this initial implementation does not support cubemap multisampling. The [cubemap implementation notes and demo](https://github.com/defold/defold/pull/13026) show how to create a target, render its faces, and bind the result to a shader.

## A clearer Material Editor

The [Material Editor redesign](https://github.com/defold/defold/pull/13311) makes material settings easier to navigate. Section headers separate the different parts of a material, and in a table you can see the entries and a dedicated form to edit the current selection. Choice boxes throughout the editor have also been made narrower.

![The redesigned Material Editor with a selected entry and its editing form](/images/posts/releases/defold-1-14-0/material_editor.webp)

## Less background work in the editor

This release [reduces unnecessary editor CPU work](https://github.com/defold/defold/pull/13232) when resizing the window, focusing property fields, and leaving a GUI scene idle with several tabs open.

In our measurements, the changes reduced JavaFX CPU work during resizing by about 34% and total process CPU usage during the tested GUI idle workload by about 25%. We measured specific workloads, so results will vary with your project and on your machine.

## Editor improvements

You can now [configure shortcuts for switching and reordering tabs](https://github.com/defold/defold/pull/13166), making it easier to move between scripts, collections, and their resources. [Wildcard patterns in `.defignore` and `.defunload`](https://github.com/defold/defold/pull/13139) also simplify working with repeated folder structures.

We also improved text shaping in the editor for complex scripts, emojis, and bidirectional text.

![Complex scripts, mixed-direction text, and emojis in the Defold code editor](/images/posts/releases/defold-1-14-0/text_shaping.webp)

## Other improvements

[Metal is now the default graphics backend on macOS](https://github.com/defold/defold/pull/13280), with OpenGL and Vulkan still selectable through the App Manifest. You can now use [shader storage buffers through dmGraphics](https://github.com/defold/defold/pull/13180) for supplying structured data to graphics and compute shaders on supported backends and devices in native extensions. Mobile fixes improve GUI safe-area positioning and rotation updates. Android R8 builds can shrink unused resources alongside Java code.

## Breaking changes and migration

This release also includes a few breaking changes, but most of them affects native extension code only. Check them though before upgrading an existing project. Use version control to secure your project, then build and test on your target platforms after updating.

[Generational game object handles](https://github.com/defold/defold/pull/13083) make retained native handles safer: deleted objects and collections are rejected even when their storage is reused. Collections can now contain up to 1,048,576 game objects, subject to project capacity settings and available resources. **This changes the native ABI:** rebuild precompiled dmSDK libraries and replace pointer-based assumptions about opaque handles with handle-sized storage. This migration regards only native C++ code and libraries, regular Lua game object code does not need to change for the new handles.

The other breaking changes are:

* **Shared Lua state is now mandatory.** It has already been enabled by default, so projects using that default don't need to take any action. Only projects that disabled it need to refactor code relying on separate globals or loaded-module caches for game object, GUI, and render scripts.
* **32-bit Windows support has been removed.** Previously, both 32-bit and 64-bit Windows targets were supported. Projects already targeting `x86_64-win32` can keep that target, but build scripts using `x86-win32` must switch to `x86_64-win32`.
* **Accelerometer input is now disabled by default.** Previously, it was enabled by default. If your game uses acceleration events, explicitly enable it in `game.project`. Games that do not use accelerometer input require no changes here.
* **The editor plugin resource-type API has changed.** Update plugins that register resource types to use the new reader and loader signatures. This only affects editor plugins using that API. See the example in [extension-simpledata migration PR](https://github.com/defold/extension-simpledata/pull/23).
* **The native render-target binding API has changed.** Native graphics code using the old `SetRenderTarget()` overload with a transient-buffer bitmask must switch to the cubemap-aware binding parameters. This C++ API migration does not require changes to existing Lua render scripts using ordinary render targets.
* **Projects using iOS links need an updated IAC extension.** If your project uses custom-scheme URLs or universal links, update IAC and test both links opened in the running app and links that launch it.
